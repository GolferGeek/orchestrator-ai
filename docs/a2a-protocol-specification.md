# Agent2Agent (A2A) Protocol Specification

**Version:** `0.2.1`  
**Source:** [Google A2A Specification](https://github.com/google/A2A/blob/main/docs/specification.md)  
**Last Updated:** January 2025

## Overview

The Agent2Agent (A2A) Protocol is an open standard designed to facilitate communication and interoperability between independent, potentially opaque AI agent systems. In an ecosystem where agents might be built using different frameworks, languages, or by different vendors, A2A provides a common language and interaction model.

## Key Goals of A2A

- **Interoperability:** Bridge the communication gap between disparate agentic systems
- **Collaboration:** Enable agents to delegate tasks, exchange context, and work together on complex user requests
- **Discovery:** Allow agents to dynamically find and understand the capabilities of other agents
- **Flexibility:** Support various interaction modes including synchronous request/response, streaming for real-time updates, and asynchronous push notifications for long-running tasks
- **Security:** Facilitate secure communication patterns suitable for enterprise environments
- **Asynchronicity:** Natively support long-running tasks and interactions that may involve human-in-the-loop scenarios

## Core Concepts

### Agent Card (Capability Discovery)
Every agent using A2A presents an **Agent Card** — a JSON "business card" describing who it is and what it can do. The Agent Card includes:
- Agent name, description, and version
- Base URL for the agent's A2A service
- List of **skills** it offers
- Authentication requirements
- Supported capabilities (streaming, push notifications, etc.)

### Agent Skills
Individual capabilities an agent has, as listed on its Agent Card. Skills are defined with:
- Unique ID within the agent
- Human-friendly name and description
- Tags for discoverability
- Example prompts or use cases
- Input/output modes (media types)

### Tasks and Artifacts
- **Task:** The fundamental unit of work managed by A2A, identified by a unique ID. Tasks are stateful and progress through a defined lifecycle
- **Artifact:** An output generated by the agent as a result of a task, composed of Parts (text, files, structured data)

### Messages and Parts
- **Message:** A communication turn between client and agent, having a role ("user" or "agent") and containing one or more Parts
- **Part:** The smallest unit of content (TextPart, FilePart, DataPart)

## Transport and Format

### Transport Protocol
- A2A communication **MUST** occur over **HTTP(S)**
- Uses **JSON-RPC 2.0** as the payload format
- Content-Type header **MUST** be `application/json`

### Streaming Transport (Server-Sent Events)
- Real-time updates via Server-Sent Events (SSE)
- Content-Type: `text/event-stream`
- Each SSE data field contains a complete JSON-RPC 2.0 Response object

## Agent Card Structure

### Complete AgentCard Schema

```typescript
interface AgentCard {
  name: string;                    // Human-readable name of the agent
  description: string;             // Human-readable description (CommonMark supported)
  url: string;                     // Base URL for the agent's A2A service (HTTPS for production)
  provider?: AgentProvider;        // Information about the agent's provider
  iconUrl?: string;               // URL to an icon for the agent
  version: string;                // Agent or A2A implementation version string
  documentationUrl?: string;      // URL to human-readable documentation
  capabilities: AgentCapabilities; // Optional A2A protocol features supported
  securitySchemes?: { [scheme: string]: SecurityScheme }; // Security scheme details
  security?: { [scheme: string]: string[]; }[]; // Security requirements
  defaultInputModes: string[];    // Input Media Types accepted
  defaultOutputModes: string[];   // Output Media Types produced
  skills: AgentSkill[];           // Array of skills (must have at least one)
  supportsAuthenticatedExtendedCard?: boolean; // Support for detailed Agent Card via auth
}

interface AgentProvider {
  organization: string;  // Name of the organization/entity
  url: string;          // URL for the provider's website/contact
}

interface AgentCapabilities {
  streaming?: boolean;              // SSE streaming support
  pushNotifications?: boolean;      // Push notification support
  stateTransitionHistory?: boolean; // Task status change history
  extensions?: AgentExtension[];    // Supported extensions
}

interface AgentSkill {
  id: string;           // Unique skill identifier within this agent
  name: string;         // Human-readable skill name
  description: string;  // Detailed skill description (CommonMark supported)
  tags: string[];       // Keywords/categories for discoverability
  examples?: string[];  // Example prompts or use cases
  inputModes?: string[]; // Overrides defaultInputModes for this skill
  outputModes?: string[]; // Overrides defaultOutputModes for this skill
}
```

## Protocol Data Objects

### Task Object
```typescript
interface Task {
  id: string;                    // Server generated unique task identifier
  contextId: string;             // Server generated ID for contextual alignment
  status: TaskStatus;            // Current status of the task
  artifacts?: Artifact[];        // Array of outputs generated by the agent
  history?: Message[];           // Optional array of recent messages
  metadata?: Record<string, any>; // Arbitrary key-value metadata
}
```

### TaskStatus Object
```typescript
interface TaskStatus {
  state: TaskState;             // Current lifecycle state
  message?: Message;            // Optional message providing context
  timestamp?: string;           // ISO 8601 timestamp (UTC recommended)
}

enum TaskState {
  submitted = "submitted",       // Task received, processing not started
  working = "working",          // Task actively being processed
  "input-required" = "input-required", // Agent requires additional input (pause)
  completed = "completed",      // Task finished successfully (terminal)
  canceled = "canceled",        // Task was canceled (terminal)
  failed = "failed",           // Task terminated due to error (terminal)
  rejected = "rejected",       // Task terminated due to rejection (terminal)
  "auth-required" = "auth-required", // Agent requires additional auth (pause)
  unknown = "unknown"          // State cannot be determined (terminal)
}
```

### Message Object
```typescript
interface Message {
  role: "user" | "agent";       // Indicates the sender
  parts: Part[];                // Array of content parts (must contain at least one)
  metadata?: Record<string, any>; // Arbitrary key-value metadata
  extensions?: string[];        // List of extension URIs that contributed
  referenceTaskIds?: string[];  // List of tasks referenced as context
  messageId: string;            // Message identifier generated by sender
  taskId?: string;              // Task identifier the message is related to
  contextId?: string;           // Context identifier
  kind: "message";              // Type discriminator
}
```

### Part Union Type
```typescript
type Part = TextPart | FilePart | DataPart;

interface TextPart {
  kind: "text";
  text: string;
  metadata?: Record<string, any>;
}

interface FilePart {
  kind: "file";
  file: FileWithBytes | FileWithUri;
  metadata?: Record<string, any>;
}

interface DataPart {
  kind: "data";
  data: Record<string, any>;    // Structured JSON data payload
  metadata?: Record<string, any>;
}

interface FileWithBytes {
  name?: string;        // Original filename
  mimeType?: string;    // Media Type (strongly recommended)
  bytes: string;        // Base64 encoded file content
}

interface FileWithUri {
  name?: string;        // Original filename
  mimeType?: string;    // Media Type (strongly recommended)
  uri: string;          // URI to file content (absolute URL recommended)
}
```

### Artifact Object
```typescript
interface Artifact {
  artifactId: string;           // Identifier for the artifact
  name?: string;                // Descriptive name for the artifact
  description?: string;         // Human-readable description
  parts: Part[];                // Content of the artifact (must have at least one)
  metadata?: Record<string, any>; // Arbitrary key-value metadata
  extensions?: string[];        // List of extension URIs that contributed
}
```

## Protocol RPC Methods

All A2A RPC methods are invoked by sending an HTTP POST request to the A2A Server's `url` with a JSONRPCRequest object and `Content-Type: application/json`.

### 1. message/send
Sends a message to initiate/continue an interaction. Suitable for synchronous request/response.

**Request:**
```typescript
interface MessageSendParams {
  message: Message;                    // The message content to send
  configuration?: MessageSendConfiguration; // Optional configuration
  metadata?: Record<string, any>;     // Request-specific metadata
}
```

**Response:** `Task | Message` (current/final state after processing)

### 2. message/stream
Sends a message AND subscribes to real-time updates via Server-Sent Events.

**Request:** Same as `message/send`
**Response:** SSE stream with `Content-Type: text/event-stream`

### 3. tasks/get
Retrieves current state of a previously initiated task.

**Request:**
```typescript
interface TaskQueryParams {
  id: string;                    // Task ID to retrieve
  historyLength?: number;        // Include N recent messages in history
  metadata?: Record<string, any>; // Request-specific metadata
}
```

**Response:** `Task` (snapshot of current state)

### 4. tasks/cancel
Requests cancellation of an ongoing task.

**Request:**
```typescript
interface TaskIdParams {
  id: string;                    // Task ID to cancel
  metadata?: Record<string, any>; // Request-specific metadata
}
```

**Response:** `Task` (state after cancellation attempt)

### 5. Push Notification Methods
- `tasks/pushNotificationConfig/set`: Configure webhook for task updates
- `tasks/pushNotificationConfig/get`: Retrieve current push notification config
- `tasks/resubscribe`: Reconnect to SSE stream for ongoing task

### 6. agent/authenticatedExtendedCard
HTTP GET endpoint to retrieve detailed Agent Card after authentication.

**Endpoint:** `{AgentCard.url}/../agent/authenticatedExtendedCard`
**Method:** GET with authentication headers
**Response:** Enhanced `AgentCard` with additional details/skills

## Authentication and Authorization

### Security Schemes
A2A treats agents as standard enterprise applications using established web security:

- **Transport Security:** HTTPS with TLS 1.2+ required for production
- **Authentication:** Via HTTP headers (Authorization: Bearer, X-API-Key, etc.)
- **Discovery:** Requirements declared in AgentCard.securitySchemes
- **Credential Acquisition:** Out-of-band process (OAuth flows, API key registration)

### Security Scheme Types
Common authentication schemes align with OpenAPI standards:
- **Bearer:** OAuth 2.0 tokens, JWTs
- **Basic:** Basic authentication
- **ApiKey:** API key in header/query/cookie
- **OpenID Connect:** OIDC discovery

### Example Security Configuration
```json
{
  "securitySchemes": {
    "oauth2": {
      "type": "oauth2",
      "flows": {
        "authorizationCode": {
          "authorizationUrl": "https://auth.example.com/oauth/authorize",
          "tokenUrl": "https://auth.example.com/oauth/token",
          "scopes": {
            "read": "Read access",
            "write": "Write access"
          }
        }
      }
    }
  },
  "security": [{ "oauth2": ["read", "write"] }]
}
```

## Error Handling

A2A uses JSON-RPC 2.0 error codes and structure:

### Standard JSON-RPC Errors
- `-32700`: Parse error (invalid JSON)
- `-32600`: Invalid Request (malformed JSON-RPC)
- `-32601`: Method not found
- `-32602`: Invalid params
- `-32603`: Internal error

### A2A-Specific Errors (-32000 to -32099)
- `-32001`: TaskNotFoundError
- `-32002`: TaskNotCancelableError
- `-32003`: PushNotificationNotSupportedError
- `-32004`: UnsupportedOperationError
- `-32005`: ContentTypeNotSupportedError
- `-32006`: InvalidAgentResponseError

## Agent Discovery

### Well-Known URI
Recommended location: `https://{server_domain}/.well-known/agent.json`

### Discovery Strategies
- **Well-Known URI:** Predefined path on agent's domain
- **Registries/Catalogs:** Curated catalogs of agents
- **Direct Configuration:** Pre-configured Agent Card URLs

### Public vs Authenticated Cards
- **Public Card:** Basic agent information, accessible without auth
- **Authenticated Extended Card:** Detailed capabilities requiring authentication
- **supportsAuthenticatedExtendedCard:** Flag indicating extended card availability

## Implementation Considerations

### For NestJS Implementation

1. **Agent Card Endpoint**
   - Serve public agent.json at `/.well-known/agent.json`
   - Implement authenticated extended card endpoint if needed
   - Include proper security scheme declarations

2. **JSON-RPC 2.0 Compliance**
   - Implement all required A2A RPC methods
   - Proper error handling with A2A-specific error codes
   - Support for batch requests if needed

3. **Task Lifecycle Management**
   - Implement proper TaskState transitions
   - Support for long-running tasks
   - Context and task ID management

4. **Security Integration**
   - HTTP-level authentication/authorization
   - JWT validation for Bearer tokens
   - Proper CORS and HTTPS configuration

5. **Streaming Support**
   - Server-Sent Events for real-time updates
   - Proper SSE formatting with JSON-RPC responses
   - Connection management and cleanup

6. **Content Type Negotiation**
   - Support for multiple input/output modes
   - Proper MIME type handling
   - File upload/download via FileParts

## Relationship to MCP

A2A and MCP are complementary protocols:

- **MCP (Model Context Protocol):** Standardizes how AI models connect to tools, APIs, and data sources
- **A2A (Agent2Agent Protocol):** Standardizes how independent AI agents communicate as peers

**Integration:** An A2A Server agent might use MCP internally to access tools while exposing A2A interface for agent-to-agent communication.
