# Centralized LLM Service Architecture

## Overview
The centralized LLM service provides a unified interface for all LLM interactions, with three-tier local model support and intelligent routing.

## Architecture Diagram
```

## Key Components

### LLMService
- Located at `apps/api/src/llms/llm.service.ts`
- Provides unified interface for all LLM interactions
- Coordinates between various specialized services
- Returns enhanced response with metadata

### CentralizedRoutingService
- Located at `apps/api/src/llms/centralized-routing.service.ts`
- Implements intelligent routing logic
- Analyzes request complexity
- Selects appropriate model tier

### LocalModelStatusService
- Located at `apps/api/src/llms/local-model-status.service.ts`
- Manages Ollama integration
- Monitors model health and availability
- Provides caching for status information

### Three-Tier Model System
- **Tier 1 (Fast Thinking)**: Complex reasoning (gpt-oss-2b, gpt-oss-20b)
- **Tier 2 (Ultra-Fast)**: Simple queries (llama3.2:1b, llama3.2:3b)
- **Tier 3 (General)**: Balanced performance (llama3.1:8b, qwen2.5:7b)

# Developer Onboarding: Centralized LLM Service

## Getting Started

### Prerequisites
- Node.js 18+
- Access to development environment
- Ollama installed for local testing

### Basic Usage

```typescript
// Import the service
import { LLMService } from '../../llms/llm.service';

// Inject the service in your class constructor
constructor(private llmService: LLMService) {}

// Generate completion
const result = await this.llmService.generateResponse(
  'Tell me about centralized LLM services.',
  {
    systemPrompt: 'You are a helpful assistant.',
    dataClass: 'public',
    policyProfile: 'standard'
  }
);

// Access response content and metadata
console.log(result.response);
console.log(result.runMetadata);
```

### Data Classification
When making requests, always set the appropriate data classification:
- `public`: Non-sensitive information
- `internal`: Internal company information
- `confidential`: Sensitive business data
- `financial`: Financial or regulated data

### Policy Profiles
Available policy profiles:
- `standard`: Default policy
- `strict`: Enhanced privacy controls
- `research`: Allows model training for research
```
