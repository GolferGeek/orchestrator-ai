# Product Requirements Document: NestJS A2A Agent Framework

## 1. Overview

### Product Name
NestJS A2A Agent Framework

### Version
1.0.0

### Date
January 2025

### Project Owner
Orchestrator AI Team

## 2. Executive Summary

Create a NestJS-based implementation of the Agent-to-Agent (A2A) protocol that provides a clean, simplified architecture where all complex logic resides in base services, while individual agents remain minimal and focused. This framework will support both MCP context agents and future LangGraph function-based agents.

## 3. Business Objectives

### Primary Goals
- Implement full A2A protocol compliance in NestJS
- Create a simplified agent architecture with minimal agent-specific code
- Enable seamless migration from FastAPI to NestJS
- Support both MCP and function-based agent implementations
- Establish foundation for future agent scaling and management

### Success Metrics
- 100% A2A protocol compliance
- 3 working agents ported from FastAPI (orchestrator, KPI agent, blog post writer)
- <50 lines of code per agent implementation
- Full test coverage for base services
- Documentation complete for agent development

## 4. Product Requirements

### 4.1 Core Architecture

#### Base API Structure
- **A2AAgentBaseService**: Core A2A protocol implementation
  - JSON-RPC message handling
  - Agent card generation
  - Task lifecycle management
  - Error handling and logging
- **MCPContextAgentBaseService**: Extends base for MCP agents
  - Markdown context loading
  - MCP client integration
  - Context-aware message processing
- **AgentWithFunctionBaseService**: Extends base for function agents
  - LangGraph integration support
  - JSON string input/output handling
  - Function routing

#### Base Controller
- **A2ABaseController**: Handles all HTTP endpoints
  - `POST /tasks` - Task processing endpoint
  - `GET /.well-known/agent.json` - A2A agent card endpoint
  - Authentication and authorization
  - Request validation and error handling

### 4.2 Agent Structure

#### Directory Layout
```
src/agents/
├── orchestrator/
│   ├── orchestrator.service.ts    # Extends base service
│   └── context/
│       └── orchestrator.md        # Context file with metadata
└── specialists/
    ├── kpi-agent/
    │   ├── kpi-agent.service.ts    # Extends base service
    │   └── context/
    │       └── kpi-agent.md        # Context file with metadata
    └── blog-post-writer/
        ├── blog-post-writer.service.ts  # Extends base service
        └── context/
            └── blog-post-writer.md      # Context file with metadata
```

#### Agent Implementation
Each agent service extends either MCPContextAgentBaseService or AgentWithFunctionBaseService and contains only:
- Agent-specific business logic (minimal)
- Context file path configuration
- Agent metadata methods

#### Unified Context File Structure
All agents use a standardized context file format serving multiple purposes:
- **Agent Metadata**: Name, description, capabilities (for programmatic agent.json generation)
- **Configuration**: Timeouts, priorities, operational settings  
- **Agent-Specific Data**: Business data, templates, calculation methods, etc.
- **MCP Context**: Knowledge base content for MCP-based agents
- **Function Context**: Reference material and examples for function-based agents

#### No Individual Controllers
- Single A2ABaseController handles all agent HTTP endpoints
- Routes requests to appropriate agent service based on URL path
- Programmatically generates agent.json from agent metadata
- No duplication of controller logic across agents

### 4.3 A2A Protocol Compliance

#### Required A2A Features
- Full JSON-RPC 2.0 support
- Complete AgentCard specification
- Message and Task object handling
- Streaming support (SSE)
- Error handling with proper A2A error codes
- Extensions support (future)

#### Agent Card Format (Programmatically Generated)
The A2ABaseController dynamically generates agent.json responses based on agent metadata:
```json
{
  "name": "Agent Name",
  "description": "Agent description", 
  "url": "https://domain.com/agents/category/agent-name",
  "version": "1.0.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": false
  },
  "defaultInputModes": ["application/json", "text/plain"],
  "defaultOutputModes": ["application/json", "text/plain"],
  "skills": [...]
}
```

Agent metadata is extracted from:
- Context file headers (YAML frontmatter or structured comments)
- Agent service class metadata methods
- Runtime information (uptime, status, etc.)
