# Remove LLM Provider/Model IDs - Switch to Name-Based System

## Problem Statement

The current LLM system uses UUID-based provider and model identification, which creates several issues:

1. **Frontend sends invalid UUIDs** that don't exist in the database
2. **Database lookups fail** causing LLM usage tracking to break
3. **Models change frequently** (Ollama models added/removed) but UUIDs are static
4. **Over-engineered complexity** for a simple use case
5. **Mismatch between requested vs actual models** used in LLM calls

## Current State

- `llm_providers` table has `id` (UUID) as primary key
- `llm_models` table has `id` (UUID) as primary key  
- `llm_usage` table references provider/model by UUID
- Frontend sends `providerId`/`modelId` UUIDs
- LLM service does database lookups to resolve UUIDs to names
- When lookups fail, usage tracking fails silently

## Desired State

- **Name-based identification**: Use provider/model names directly
- **No database lookups**: LLM service works with names immediately
- **Dynamic model support**: Add/remove models without database changes
- **Accurate tracking**: Record actual provider/model used, not requested
- **Simple API**: Frontend sends `{provider: "ollama", model: "deepseek-r1:14b"}`

## Success Criteria

1. **Agent LLM calls are tracked properly** with correct provider/model names
2. **Frontend can select providers/models by name** without UUIDs
3. **Adding new Ollama models** doesn't require database changes
4. **LLM usage records show actual models used**, not requested
5. **No more UUID-based lookups** in LLM service

## Technical Requirements

### Database Changes
- Remove `id` columns from `llm_providers` and `llm_models` tables
- Use `name` as primary key for both tables
- Update `llm_usage` table to use `provider_name`/`model_name` instead of IDs
- Migrate existing data to use names instead of UUIDs

### API Changes  
- `/llm/providers` endpoint returns name-based structure
- LLM generation endpoints accept provider/model names
- Remove all UUID-based provider/model lookups

### Frontend Changes
- Update model selection UI to use names instead of UUIDs
- Store selected provider/model names in local state
- Send names in LLM requests instead of UUIDs

### Backend Changes
- Remove `getProviderAndModel()` database lookup method
- Update LLM service to work with names directly
- Record actual provider/model from LLM responses
- Update all interfaces to use names instead of IDs

## Implementation Strategy

1. **Database migration** - Remove IDs, switch to names
2. **Backend API updates** - Remove UUID lookups, use names
3. **Frontend updates** - Send names instead of UUIDs
4. **Testing** - Verify agent calls are tracked properly
5. **Cleanup** - Remove unused ID-based code

## Risks & Mitigation

- **Data migration complexity** - Create careful migration scripts
- **Breaking changes** - Coordinate frontend/backend updates
- **Model name conflicts** - Ensure unique naming conventions

## Timeline

Target: Complete within 1-2 development sessions
Priority: High (blocking agent LLM usage tracking)
