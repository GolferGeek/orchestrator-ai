# Residential Internet Server Setup PRD

## Overview
Set up Orchestrator AI server to be accessible via `orchestratorai.io` from a residential internet connection. This involves configuring dynamic DNS, router port forwarding, SSL certificates, and monitoring to handle the challenges of residential internet including dynamic IP addresses and ISP restrictions.

## Core Features

### 1. Dynamic DNS Configuration
- **What it does**: Automatically updates DNS records when residential IP changes
- **Why it's important**: Residential IPs change frequently, making manual DNS updates impractical
- **How it works**: Uses Cloudflare API with ddclient to monitor IP changes and update DNS records

### 2. Router Port Forwarding
- **What it does**: Routes external traffic to internal server on specific ports
- **Why it's important**: Makes local server accessible from the internet
- **How it works**: Configures router to forward ports 80, 443, 9000, 9001 to server

### 3. SSL Certificate Management
- **What it does**: Provides secure HTTPS access with automatic certificate renewal
- **Why it's important**: Ensures secure communication and browser compatibility
- **How it works**: Uses Let's Encrypt with Certbot for free SSL certificates

### 4. Server Network Configuration
- **What it does**: Assigns static local IP and configures firewall
- **Why it's important**: Prevents IP conflicts and ensures consistent port forwarding
- **How it works**: Configures netplan for static IP and UFW firewall rules

### 5. Monitoring and Health Checks
- **What it does**: Monitors service health and automatically restarts if needed
- **Why it's important**: Ensures high availability and catches issues early
- **How it works**: Cron jobs run health checks and restart services if down

## Technical Architecture

### System Components
- **Dynamic DNS Client**: ddclient for Cloudflare integration
- **Web Server**: Nginx for SSL termination and reverse proxy
- **SSL Certificate Manager**: Certbot for Let's Encrypt certificates
- **Firewall**: UFW for port management
- **Monitoring**: Custom health check scripts with cron

### Data Models
- **DNS Records**: A records for domain and subdomains
- **Network Configuration**: Static IP assignment and routing
- **SSL Certificates**: Certificate files and renewal configuration
- **Log Files**: Application and system logs with rotation

### APIs and Integrations
- **Cloudflare API**: For DNS record updates
- **Let's Encrypt API**: For SSL certificate issuance
- **IP Detection Service**: ipinfo.io for external IP detection

### Infrastructure Requirements
- **Server**: Ubuntu/Debian system with admin access
- **Router**: Admin access for port forwarding configuration
- **Domain**: orchestratorai.io with Cloudflare DNS
- **Internet**: Residential connection with port forwarding capability

## Logical Dependency Chain

### Foundation First
1. **Prerequisites verification** - Must confirm access and ownership before proceeding
2. **Network configuration** - Server must have stable network before external access
3. **Router configuration** - External access requires proper port forwarding

### Service Layer
4. **Dynamic DNS** - Domain must resolve correctly for SSL and access
5. **SSL certificates** - HTTPS requires valid certificates
6. **Nginx configuration** - Reverse proxy needed for proper routing

### Monitoring and Validation
7. **Health monitoring** - Ensures ongoing reliability
8. **Testing and validation** - Confirms everything works correctly

## Risks and Mitigations

### Technical Challenges
- **Dynamic IP changes**: Mitigated by automated DNS updates
- **SSL certificate expiry**: Mitigated by automatic renewal
- **Service crashes**: Mitigated by health check scripts
- **Router configuration**: Mitigated by detailed documentation and testing

### ISP Restrictions
- **Port blocking**: Mitigated by using standard web ports
- **Rate limiting**: Mitigated by monitoring and optimization
- **TOS violations**: Mitigated by using business internet for production

### Resource Constraints
- **Server resources**: Monitor CPU/memory usage
- **Bandwidth limitations**: Implement rate limiting
- **Storage for logs**: Configure log rotation
